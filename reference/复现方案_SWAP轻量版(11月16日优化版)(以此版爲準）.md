# 复现选型与实施方案：SWAP 轻量版（基于 WMP）

> **结论：选 SWAP，做“轻量复现”。**
> 关键原因：SWAP 的前作 **WMP 已经开源了完整底座**（Isaac Gym + 深度相机 + RSSM 世界模型 + 地形课程 + AMP），
> Apache-2.0，410 stars，2026 年 10 月还在更新。
> SWAP 只在这个底座上加“对称等变”，而论文里的 `SWAP (w/o Eq)` 基线**就是 WMP**。
> 复现可以沿着论文的消融逐级做，每一步都有现成参考。
>
> **2026-10 更新**：机器人已由 A1 改为 **Unitree Go2**（导师要求；Go2 数据集更多，实验室也有真机）。
> 两者同为 12 自由度，迁移约 2 天，详见 `Go2迁移改动清单.md`；下文命令和指标已同步为 Go2。
>
> **前提**：本方案已冻结为 **512 env、10k ≈ 24 h**（24 GB 4090 可跑）。
> WMP 默认的 4096 环境约 23 GB、10k ≈ 39 h，本方案**不采用**，也不要改回去。
> 真爆显存时只降 `camera_num_envs`，并重跑同配置 R0-LHR 基线；8 GB 笔记本请走 PointWalker-lite 备选。
>
> **2026-11-16 修订（对齐原论文）**：改为**论文同款四组消融**（不是 2×2 因子设计）——
> **R0 基线（WMP）**、**R1 SymLoss 软约束**、**R2 等变世界模型 + 普通 Actor-Critic**、
> **R3 等变世界模型 + 等变 Actor-Critic**。
> 四组**统一在“左高右低（LHR）”的单侧倾斜地形上训练**（tilted box / stair / gap），
> **评估分两套：同向 LHR（训练分布内）和镜像 RHL（右高左低，分布外）**，必须分开报告。
> **命名约定**：**R0 = 阶段 3 用固定 LHR 从零重训的基线**；阶段 1 已完成的旧 10k
>（经检查**不是**固定 LHR）记为 **R0-pilot**，只作环境/冒烟参考，**不进入任何四组表、图、视频对比**。
> 基线仍为 **512 env × 10k ≈ 24 h**，此前阶段不再改动；四组均从零训练 10k、同配置同预算、同地形种子；
> 每次评估统一 **200 次/格**，并强制标注“条件 / 训练地形 / 模型 / 评估地形 / 难度 / 试验数”。
> 不做“只等变 Actor-Critic、世界模型普通”的组（论文没有这一组）；AMP 判别器不做等变
>（标准 AMP + 参考动作镜像增广）。详见阶段 3、阶段 4~6B 和“评估标注规范”。

## 一、人话版：两个工作到底在干什么

### SWAP

先让网络在“潜空间”里学一个世界模型（RSSM）：看当前观测，预测下一步会看到什么；
再要求这个潜空间、演员网络、评论家网络都满足左右镜像对称（等变网络）；
还要用 AMP（对抗运动先验）模仿动物步态；最后把世界模型和 PPO 策略一起训练。

**比喻**：闭着眼睛在脑子里放一部“小电影”，预测下一秒的画面；
还要求这部电影左右镜像之后也成立。电影放得越准，走路越稳。

### WMP（SWAP 的底座）

WMP 是 2024 年的论文 *World Model-based Perception for Visual Legged Locomotion*。
它已经实现了：
- 深度相机（Isaac Gym camera）；
- RSSM 世界模型（DreamerV3 风格，潜变量 32×32）；
- 地形课程（wave/slope/stairs/discrete/gap/pit/tilt/crawl）；
- AMP 对抗运动先验（自带 trot/hop 动作数据）；
- PPO + 世界模型特征的训练循环；
- 机器狗的 URDF 和配置（自带 A1；本项目已迁移到 **Go2**，见 `Go2迁移改动清单.md`）。

SWAP 论文里的 `SWAP (w/o Eq)` 基线，本质上就是 WMP。
所以复现 SWAP 不是“从零造世界模型”，而是“**把 WMP 改造成左右对称版**”。


## 二、关键发现：

  - `rsl_rl/runners/wmp_runner.py`：训练循环；
  - `rsl_rl/algorithms/amp_ppo.py`、`amp_discriminator.py`：AMP + PPO；
  - `legged_gym/envs/base/legged_robot.py`：深度相机、地形、课程；
  - `datasets/mocap_motions/`：trot/hop 参考动作；
  - `resources/robots/a1/`：A1 的 URDF 和 mesh（保留作对照）；
  - `resources/robots/go2/`：本项目新增的 Go2 URDF 和 mesh。
- 训练命令（Go2）：


### 发现 2：论文的消融就是你的复现路线图

SWAP 论文里的四组消融，本项目逐一对应：

| 论文里的名字 | 实际是什么 | 本项目的组 |
|---|---|---|
| `SWAP (w/o Eq)` | 标准 WMP，没有任何对称约束 | **R0 基线**（阶段 3 用 LHR 重训 10k） |
| `SymLoss` | 普通网络 + 对称性软惩罚（不改网络结构） | **R1 SymLoss 软约束** |
| `SWAP (w/o Eq-Policy)` | 世界模型等变，actor-critic 普通 | **R2 等变世界模型** |
| `SWAP` | 世界模型 + actor-critic 都等变 | **R3 等变世界模型 + 等变 Actor-Critic** |

注意：**没有“只等变 actor-critic、世界模型普通”这一组**——论文没有，本项目也不做。
四组都从零训练 10k，训练地形统一为“左高右低（LHR）”的单侧倾斜 box/stair/gap；
评估分同向 LHR 和镜像 RHL 两套，不能混成一个“成功率”。
**已完成的旧 10k 不是固定 LHR，记为 R0-pilot，不进入四组表；正式 R0 在阶段 3 重训。**

这意味着你不必一上来就啃最难的“等变 RSSM”。
先重训 LHR 基线（R0），再加 SymLoss 软约束（R1），再把世界模型换成等变的（R2），
最后把 actor-critic 也换成等变的（R3）；每一步都是一个正式消融，每一步都能写进报告。

### 发现 3：对称网络 / 等变策略有现成参考代码

- **SymmLoco**（IROS 2024）：https://github.com/HybridRobotics/SymmLoco
  - Isaac Gym + rsl_rl + MorphoSymm；
  - 提供 `emlp`（等变 MLP）的 actor-critic；
  - 训练命令 `--task=cyber2_push_door_emlp`；
  - 64 stars，2026-10-18 还在更新。
- **morphosymm-rsl-rl**：https://github.com/iit-DLSLab/morphosymm-rsl-rl
  - RSL-RL 的形态对称扩展（IsaacLab 版）。
- **escnn**：https://github.com/QUVA-Lab/escnn
  - 标准的 Z2 等变 CNN 库，用来做深度图编码器/解码器。
- **mdp-homomorphic-networks**：https://github.com/ElisevanderPol/mdp-homomorphic-networks
  - MDP 同态网络参考实现。

你不需要从数学公式开始推导，可以先“抄结构 + 写单元测试”。

### 发现 4：论文缺的超参数，WMP 代码里有

SWAP 论文没给潜变量维度、学习率、batch、序列长度、β、更新间隔 k。
WMP 的 `dreamer/configs.yaml` 给了：
- `dyn_hidden: 512`、`dyn_deter: 512`、`dyn_stoch: 32`、`dyn_discrete: 32`；
- `batch_size: 16`、`batch_length: 64`、`train_ratio: 512`；
- `model_lr: 1e-4`、`kl_free: 1.0`、`dyn_scale: 0.5`、`rep_scale: 0.1`；
- `pretrain: 100`。

这些数值不一定和 SWAP 完全一致，但足够让你跑起来，不用瞎猜。

### 发现 5：评价实验在仿真里就能做

SWAP 的核心实验是“**只在单侧倾斜地形上训练，直接测试镜像地形**”（论文 Fig. 3）。
WMP 的地形生成器已经有 `tilt` 和 `gap`，你只需要在评估时把高度图左右翻转，
就能复现这个实验。不需要真机、不需要 Apollo。

## 三、为什么选 SWAP（对着你的两个标准）

### 标准 1：已有框架成熟，少写额外代码

| 模块 | SWAP（基于 WMP） | PointWalker |
|---|---|---|
| 训练算法 | WMP 已实现 PPO + AMP + 世界模型训练循环 | 标准 PPO 要自己接注意力 |
| 世界模型 | WMP 已实现 RSSM（约 1100 行） | 不需要 |
| 深度相机 | WMP 已实现 Isaac Gym camera | 需要自己写点云射线 |
| 地形 | WMP 已实现 9 类地形 + 课程 | 你的仓库只有平面，需移植 |
| 步态先验 | WMP 自带 AMP + trot/hop 数据 | 不需要 |
| 对称网络 | SymmLoco/MorphoSymm 可参考 | 不需要 |
| 复用现有代码 | **WMP 直接就是底座** | 只能复用 PPO 和 MuJoCo |
| 需要从零写的部分 | 等变层 + 集成（约 500~1000 行） | 点云 + 注意力 + PPO 集成（约 1000 行） |
| 有没有“跑通”的参考 | **有：先跑 WMP 基线** | 没有，第一步就是新代码 |

### 标准 2：任务能拆给 agent 执行

SWAP 的复现可以拆成一条很清晰的流水线：

1. 装 WMP，跑 5 个 iteration；
2. 阶段 3 先重训 LHR 基线 R0（512 env × 10k ≈ 24 h；旧的非 LHR 10k 记为 R0-pilot）；
3. 写评估脚本，先拿到 R0 在同向 LHR 和镜像 RHL 上的成功率；
4. 在普通 actor/critic 上加 SymLoss 软惩罚，写单元测试（R1）；
5. 训练 R1 10k，和 R0-LHR 对比；
6. 把 encoder/decoder 换成 SE-CNN；
7. 把 GRU 换成 SE-GRU / 成对潜变量（R2）；
8. 训练 R2 10k，和 R0-LHR 对比；
9. 把 R2 的等变世界模型接上 SE-MLP actor/critic（R3）；
10. 训练 R3 10k，评估、画图、写报告。

每一步都有明确的输入输出和验收标准，而且**前一步永远是一个能跑的版本**。
就算第 6~9 步做不出来，你也有 R0 + R1 的完整结果（WMP 基线 + SymLoss 软约束）；
如果 R1 也做不出来，R0 的同向/镜像评估仍是一个合理的保底交付。
注意：论文的 `SWAP (w/o Eq-Policy)` 是 **R2（等变世界模型 + 普通 actor/critic）**；
R1 是 `SymLoss` 软约束，两者不是一回事，报告里必须写清楚。

PointWalker 没有这种“保底版本”：点云写错、注意力不收敛、PPO 接错，
你手里可能一个能走的策略都没有。

### 标准 3：算力和时间

| | SWAP / WMP（本方案） | PointWalker |
|---|---|---|
| 并行环境 | **512（已冻结）**；WMP 默认 4096 不采用 | 8192（论文） |
| 显存 | 24 GB 4090 内可跑；WMP 默认 4096 约 23 GB | 未公开；轻量版 6~10 GB |
| 单次训练 | **10k iter ≈ 24 h**（512 env）；默认 4096 约 39 h | 4×5090 约 50 h（论文） |
| 降配 | **不再降 `num_envs`**；只降 `camera_num_envs` 并重跑 R0-LHR | 512~1024 envs，约 2~6 h/次 |
| 主要耗时 | 深度图渲染 | 点云射线 + 注意力 |

**诚实说**：本方案一次训练约 24 小时，比 PointWalker-lite 的单次训练久。
但它的“第一次能跑”来得早：装好就能看 WMP 走路。
PointWalker 要自己写 2~3 周才第一次看到策略。

WMP 作者在 issue #18 里确认，主要耗时是深度图渲染；
所以显存真不够时，只调 `depth.camera_num_envs`，不要动 `num_envs=512`。
相机环境数一旦改过，必须重跑同配置 R0-LHR，否则四组不可比。

### 标准 4：失败时的退路

SWAP 的退路是**层层降级**：
- 完整 SWAP（R3）做不出来 → 做 `SWAP (w/o Eq-Policy)`（R2：等变世界模型 + 普通 actor/critic）；
- 等变世界模型也做不出来 → 保留 R1（SymLoss 软约束）或 R0 基线 + 同向/镜像评估；
- WMP 跑不起来 → 再考虑 PointWalker-lite。

PointWalker 的退路是“换输入表示”：
- 注意力不行 → mean pooling；
- 点云不行 → 高度图；
- 但换完以后，离论文的核心越来越远。

## 四、轻量化复现指标（不上真机）

### 机器人

直接用 **Unitree Go2** 跑通。WMP 自带的是 A1，但导师要求换 Go2；
两者都是 12 自由度、4 只脚、8 个 thigh/calf 刚体，网络输入输出维度完全一样，
所以迁移只改 URDF 路径、初始高度、站立高度、相机位置、动作顺序、任务名 6 处，
约 2 天完成，详见 `Go2迁移改动清单.md` 和 `go2_migration/README.md`。
A1 的配置和资产保留在仓库里，作为“迁移失败时的对照组”，不要删除。

### 四档指标

| 档位 | 做什么 | 验收指标 | 时间 |
|---|---|---|---|
| **保底** | R0 基线（Go2，**阶段 3 用 LHR 重训 512 env × 10k**） | 3 种 LHR 地形（tilted box/stair/gap）能走；成功率 > 50%；有视频 | 阶段 3（约 1 天） |
| **标准** | R1 SymLoss 软约束 + R2 等变世界模型，两组都跑完 | 镜像 RHL 成功率高于 R0-LHR；复现论文 Fig. 3 的趋势；R1 是软惩罚，需同时报告“对称误差”而不是宣称严格等变 | 3~5 周 |
| **冲刺** | R3 等变世界模型 + 等变 Actor-Critic（完整 SWAP-lite） | 镜像 RHL 重构误差上升幅度小于 R0-LHR（论文 Fig. 3c）；镜像/攀箱成功率优于 R1、R2 | 5~7 周 |
| **游刃有余**（可选） | 爬高 / 跳远**全量冲刺**：R3（等变 WM + 等变 AC）为主、R0-LHR 为对照；Go2 先追归一化 3.0×L / 3.0×H（约 1.16 m / 1.00 m），达不到再降到 2.0× / 1.5× | 至少一个技能达到 ≥2.0×；同难度下 R3 ≥ R0-LHR；有对比视频 | 7~8 周（仅缓冲期） |

### 训练与评估次数（直接回答）

| 组 | 条件 | 训练 | 单次时长（24 GB 4090） | 评估 |
|---|---|---|---|---|
| R0 | 基线 WMP（LHR 重训） | 10k（512 env，固定 LHR） | ~24 h（阶段 3） | 18 格 × 200 次 |
| R1 | SymLoss 软约束 | 1k 冒烟 + 10k | ~2~3 h + ~24 h | 18 格 × 200 次 |
| R2 | 等变世界模型 + 普通 AC | 1k 冒烟 + 10k | ~2~3 h + ~24 h | 18 格 × 200 次 |
| R3 | 等变世界模型 + 等变 AC | 1k 冒烟 + 10k | ~2~3 h + ~24 h | 18 格 × 200 次 |

> 1 格 = 1 种地形（box/stair/gap）× 1 个评估方向（LHR/RHL）× 1 个难度（1/2/3）；
> 3 × 2 × 3 = **18 格**。四组**训练地形都只有 LHR**，RHL 只在评估时出现。

- **全量训练 4 轮**（R0-LHR / R1 / R2 / R3），每轮 10k ≈ **24 h**，合计 **~96 h**；
- 1k 冒烟 4 轮（R0 重训前 1 轮 + R1/R2/R3 各 1 轮），合计 **~10~12 h**；
- 评估 4 个 checkpoint（R0-LHR/R1/R2/R3）× 18 格 × 200 次 = **14,400 次**，
  约 **1~2 h/checkpoint**，合计 **~4~8 h**；
- 主路径 GPU 时间约 **110~120 h ≈ 5 天**（不含调试和失败重跑）；
- 阶段 9 可选微调另加约 **20~40 h**（R0-LHR 对照 + R3 主选，爬高/跳远各一组）。

### 评估标注规范（强制）

每次评估、每张表、每张图、每段视频，标题/表头必须写清下面 6 项，缺一项视为无效结果：

```
[条件]   R0 基线（LHR 重训） / R1 SymLoss / R2 等变WM+普通AC / R3 等变WM+等变AC
[训练地形] 左高右低（LHR）单侧倾斜 box/stair/gap；四组相同
[模型]   runs/<组>/<seed>/model_<iter>.pt
[评估地形] 同向 LHR（训练分布内） / 镜像 RHL（右高左低，分布外）
[地形/难度] box|stair|gap / level 1|2|3
[试验数] 200 次，固定命令、确定性动作均值
```

四组 × 两个评估方向的关系：

| 组 | 训练地形 | 评估：同向 LHR | 评估：镜像 RHL |
|---|---|---|---|
| R0 基线 | LHR | 9 格 × 200 | 9 格 × 200 |
| R1 SymLoss | LHR | 9 格 × 200 | 9 格 × 200 |
| R2 等变 WM + 普通 AC | LHR | 9 格 × 200 | 9 格 × 200 |
| R3 等变 WM + 等变 AC | LHR | 9 格 × 200 | 9 格 × 200 |

> 表中的 **R0 一律指阶段 3 的 R0-LHR（重训版）**；旧的 R0-pilot 不进入任何四组表/图。
> 模型路径也必须写 `runs/R0_LHR/...` 或等价命名，不能和 R0-pilot 混用。

结果表统一用这个表头（一行 = 一个条件 × 一个评估地形 × 一个难度）：

| 条件 | 训练地形 | 模型/迭代 | 评估地形 | 地形/难度 | 试验数 | 成功率 |
|---|---|---|---|---|---|---|
| R3 | LHR | `runs/R3/seed0/model_10000.pt` | RHL 镜像 | box / level 2 | 200 | 78% |

**硬规则**：

1. **不要把 LHR 和 RHL 平均成一个数**。同向成功率是“训练分布内表现”，镜像成功率是“对称泛化”，
   两者必须分列；镜像 gap = 同向成功率 − 镜像成功率。
2. **不要只写“成功率”**。任何结果必须带“组别 + 模型 + 训练地形 + 评估地形 + 难度 + 试验数”。
3. **不要把 R2 和 R3 的模型混用**。R2 的 actor/critic 是普通 MLP；R3 是 SE-MLP，二者 checkpoint 不可互换。
4. **R1 是软约束**，不能因为“看起来对称”就写成“等变网络”；要同时报告对称误差和镜像成功率。
5. 论文 Fig. 3a 的评估口径就是“只在 LHR 训练，直接测 RHL 镜像”，本项目照此执行；
   R0 的同向/镜像差就是论文 Fig. 3b 要复现的基线掉点。

### 明确不做的事

- 不做 Apollo 真机；

### 阶段 4：R1 SymLoss 软约束（代码 + 单测 + 1k 冒烟 + 10k，约 3~5 天）

**R1 的定义**：网络结构完全不变——普通 WMP + 普通 MLP actor/critic；
只在 PPO 损失里加一项“镜像一致性”软惩罚，让策略（可选价值函数）在镜像观测上尽量一致。
这不是硬等变，输出不保证严格满足 `mu(F(o)) = F_a(mu(o))`，所以报告要同时给出“对称误差”。

**做什么**
1. 用与 R0-LHR 相同的普通 actor/critic 和普通世界模型结构，**不加任何 SE 层**；
   R1 **从零训练 10k**，不加载 R0-LHR 的 checkpoint（四组同预算）；
2. 先写 `symmetry.py`（如果还没写），实现观测/动作/潜变量的镜像：
   - `F_obs(obs)`：观测镜像；
   - `F_act(action)`：动作镜像；
   - `F_latent(z)`：潜变量成对交换（R1 暂时不用，R2/R3 会用）；
   - 各分量的镜像规则（论文 Table I）：
     - base 线速度：`(vx, -vy, vz)`；
     - base 角速度：`(-wx, wy, -wz)`；
     - projected gravity：`(gx, -gy, gz)`；
     - 命令：`(vx, -vy, -wz)`；
     - 关节位置/速度/动作：左右腿交换，hip abduction 取负；
       Go2 顺序是 FL,FR,RL,RR，左右交换排列为 `[3,4,5,0,1,2,9,10,11,6,7,8]`，
       hip 下标 `[0,3,6,9]` 取负（详见 `Go2迁移改动清单.md` 4.4 节）；
     - 接触标志：左右脚交换；
     - 随机化参数：左右交换/取负。
3. 在 PPO loss 里加软惩罚（默认只罚 actor，更接近论文引用的 SymLoss [18]）：
   ```python
   h = h.detach()              # SymLoss 只更新 actor，不反传到普通世界模型
   mu_m = actor(F_obs(o), h)   # 关键：h 固定为同一份，不镜像
   mu   = actor(o, h)
   L_sym = ((mu_m - F_act(mu)) ** 2).mean()
   # 可选：+ beta * ((critic(F_obs(o), h) - v) ** 2).mean()，beta 默认 0
   loss = loss_ppo + lambda_sym * L_sym
   ```
   - R1 的 `h` 来自普通 WMP，不满足镜像等变；软惩罚里把 `h` 固定并 detach，
     只惩罚 `o` 相关的部分。`h` 的不对称仍会残留，所以 R1 **只能减小、不能消除**镜像 gap；
   - 默认 `beta = 0`，只罚 actor；如果后面想加 critic 项，单独开开关并记录；
   - `lambda_sym` 从 **0.01~0.1** 起调；1k 冒烟时同时看“对称误差下降”和“任务 reward 不崩”；
   - 记录最终 `lambda_sym`（以及 `beta`），写进报告。
4. 单元测试：
   - 固定同一份 `h`，构造一个“镜像不变”的 dummy actor，`L_sym ≈ 0`；
   - 构造一个明显不对称的 dummy actor，`L_sym > 0`；
   - 反传检查 actor 有梯度；若开了 `beta`，critic 也有梯度；
   - 验证 `F(F(x))=x`。
5. 1k 冒烟：无 NaN、reward 正常、`play.py` 能走；
6. 训练 **R1 全量 10k（约 24 h）**，200 次/格评估（LHR + RHL），和 R0-LHR 对比。

**验收**
- 单元测试通过（dummy 对称 loss≈0、不对称 loss>0；`F(F(x))=x`）；
- 1k 冒烟能走，无 NaN；
- R1 全量 10k 完成，有 200 次/格的 **LHR/RHL 分列**成功率表；
- 记录平均对称误差 `||mu(F(o), h) - F_a(mu(o, h))||`（`h` 固定），确认它比 R0-LHR 小；
- 镜像 gap 比 R0-LHR 小（趋势即可，不要求论文的绝对值）。

**卡住怎么办**
- 不会写 SymLoss：保持默认 `beta=0`，先只罚 actor；跑通后再考虑加 critic；
- `lambda_sym` 太大导致 reward 崩：降到 0.01 或 0.005，先保证任务能学；
- `lambda_sym` 太小没效果：看对称误差曲线，逐步加；不要一次加到 1.0；
- **不要给 R1 加 SE 层**：R1 的定义就是“普通网络 + 软惩罚”；
- **不要声称 R1 是“等变网络”**：它是软约束，报告里写“对称误差下降”而不是“严格等变”。

### 阶段 5：R2 等变世界模型 + 普通 Actor-Critic（2~4 周，核心）

**R2 的定义**：actor/critic **保持普通 MLP**，世界模型完整等变（SE-CNN + SE-GRU + 成对先验/后验）。
这一步是论文的 `SWAP (w/o Eq-Policy)`；产出 **R2 全量 10k（约 24 h）**。
注意：R2 只改世界模型，**不要顺手把 actor/critic 也换成 SE**；那是 R3 的事。

**做什么**
1. **SE-CNN 编码器/解码器**：
   - 用 `escnn` 的 Z2 等变卷积替换 WMP 的 depth encoder/decoder；
   - 第一层把 trivial field 提升到 regular representation（成对镜像通道）；
   - 验证：`decoder(encoder(F_img(x))) = F_img(decoder(encoder(x)))`。
2. **SE-GRU**：
   - 把 RSSM 的 GRU 输入/输出按左右配对排列；
   - 权重约束成块对角/反对角，保证 `f(F_l(h), F_l(z), F_a(a)) = F_l(f(h,z,a))`；
3. **配对潜变量**：
   - 把 `dyn_stoch` / `dyn_deter` 设为偶数；
   - 相邻两维是一对左右特征；
   - prior/posterior 的均值和方差也按对约束。
4. 先只改 encoder/decoder，再改 GRU，最后改 prior/posterior；
5. 每改一块，跑 1k iterations，确认重构误差和策略都没崩；
6. 全部通过后，训练 **R2 全量 10k（约 24 h）**，200 次/格评估（LHR + RHL）。

**验收**
- 深度图重构误差在 LHR 训练地形上不显著变差；
- RHL 镜像地形上重构误差比 R0-LHR 低（论文 Fig. 3c 的趋势）；
- 1k 冒烟能走；R2 全量 10k 完成，有 200 次/格的 **LHR/RHL 分列**成功率表；
- R2 的镜像 gap 比 R0-LHR 小。

**卡住怎么办**
- escnn 和 Isaac Gym 的 PyTorch 版本冲突：先用纯 PyTorch 手写 Z2 等变卷积（只有 2 个群元素，不难）；
- SE-GRU 太难：先不做，保留普通 GRU；此时只能写“对称感知”，不能写“等变世界模型”，
  并在报告里明确降级；不要偷偷把它算成 R2 的完整版；
- 训练不稳定：冻结世界模型，只训策略；或先训世界模型，再训策略。

### 阶段 6A：R3 等变世界模型 + 等变 Actor-Critic（约 1 周，核心）

**做什么**
1. 在 R2 的等变世界模型上，把 actor/critic 换成 SE-MLP：
   - actor：`mu(o_H, c, h) = SE_MLP(o_H, c, h)`，
     满足 `mu(F_obs(o), F_l(h)) = F_act(mu(o, h))`；
   - critic：`V(o_priv, h) = SE_inv(o_priv, h)`，
     满足 `V(F_obs(o), F_l(h)) = V(o, h)`；
   - `h` 来自 R2 的成对潜变量，用 `F_l(h)` 镜像；`h` 走 SE 分支，**不再固定**；
   - 保持 `sg(h)`；**不要复用 R2 的普通 actor/critic**；
   - R3 **从零训练 10k**，不加载 R0-LHR/R1/R2 的 checkpoint；四组同预算、同配置、同地形种子（LHR）。
2. 单元测试：编码器/GRU/先验后验/actor/critic 全部通过；
   全链路测 `actor(F_obs(o), F_l(h)) = F_act(actor(o, h))`，此时 `h` **不固定**；
   同时测 `F_l(F_l(h)) = h`；
3. 1k 冒烟：无 NaN、loss 正常、play 能走；
4. **R3 全量 10k（约 24 h）**；
5. 200 次/格评估：3 地形 × 2 方向（LHR/RHL）× 3 难度。

**验收闸门**
- **G6A-0 单测**：float64、随机初始化、eval 模式；SE 线性层 < 1e-6，其余 < 1e-4；
  `F(F(x))=x`；`F_l(F_l(h))=h`。
- **G6A-1 冒烟**：1k iter 无 NaN，`play.py` 能走，显存峰值记录。
- **G6A-2 聚合指标（R3 vs R0-LHR）**：
  - LHR 同向：R3 的 9 个 LHR 格聚合成功率 ≥ R0-LHR 聚合 − 5 个百分点；
  - RHL 镜像：记 `gap = LHR 成功率 − RHL 成功率`；R3 的聚合 gap ≤ R0-LHR 的 gap − 5 个百分点，
    且 9 个 RHL 格至少 6 格比 R0-LHR 好；
  - 重构误差：R3 在 RHL 的误差上升幅度 < R0-LHR 的上升幅度，至少小 1 cm（或 20%）。
- **G6A-3 四组表**：R0-LHR/R1/R2/R3 各 200 次/格；按“训练地形 LHR / 评估地形 LHR、RHL”分列；
  至少复现“镜像成功率”或“攀箱成功率”的排序之一。

**卡住怎么办**
- 不会写 SE-MLP：先抄 SymmLoco 的 `emlp`（`W = A⊗I2 + B⊗P2`），改成 Go2 的观测/动作维度；
- LHR 同向掉超过 5 个点：先查等变实现和归一化层，不要带病进 6B；
- RHL 镜像 gap 没缩小：先确认 R3 的 actor/critic 真的是 SE-MLP（不是 R2 的普通 AC），
  再确认 `h` 走了 `F_l(h)`；最后看重构误差和 R2 的结果，判断是 WM 还是 actor 的问题；
- 显存爆：只降 `camera_num_envs`，并重跑同配置 R0-LHR。

### 阶段 9（可选，最后的“游刃有余”）：爬高 / 跳远全量冲刺

**什么时候才能启动**

只有同时满足下面三条才启动，否则直接跳过：

1. 阶段 0~7 的核心交付全部完成（R0 基线、镜像评测、四组对照、报告初稿）；
2. 报告和视频已经能交差，就算这个阶段完全失败也不影响成绩；
3. 服务器还有 ≥5 天连续可用时间。

**目标：先追全量，达不到再降级**

SWAP 论文的“全量”不是随便一个绝对米数，而是按机器人尺寸归一化的：

- 跨沟距离 = **3.0 × L**（L = 前后髋距）；
- 爬台高度 = **3.0 × H**（H = 站立髋高）。

对论文的 Apollo（70×55 cm，72 kg）：3.0×L = **2.13 m**，3.0×H = **1.63 m**。
对本项目的 Go2（URDF 里 L = 0.3868 m，站立 H ≈ 0.33 m）：

- 3.0×L ≈ **1.16 m**；
- 3.0×H ≈ **1.00 m**。

所以“追全量”：

   用 Go2 追“归一化全量” **3.0×L / 3.0×H**（约 1.16 m / 1.00 m）。
   这和论文的 2.13 m / 1.63 m 是同一把尺子，只是机器人小一号。

**止损线**

- 缓冲期内至少做到 **2.0×L / 2.0×H**（Go2 约 0.77 m / 0.66 m）；
- 做不到就按 2.0× → 1.5× → 1.0× 逐级降，最后退到小尺寸定性演示；
- 不要为了 3.0× 无限调参，核心交付永远优先。

**为什么放最后**

这两个任务奖励难调、训练容易崩、单次训练时间长，是“锦上添花”，不是“雪中送炭”。
核心交付没冻结之前，绝对不要碰。

**怎么做（按顺序）**

> 阶段 9 的爬高/跳远是**独立协议**，不参与四组主实验的 LHR/RHL 对比；
> 结果单独标注“阶段 9 / 爬高或跳远 / 难度 / 试验数”，不要和阶段 6B 的四组表混在一起。

1. **地形直接用米数，不要只调 difficulty**
   - WMP 已有 `gap_terrain(gap_size)` 和 `climb_terrain(depth)`；
   - 全量目标：`gap_size = 1.16`（3.0×L）、`depth = 1.00`（3.0×H）；
   - 注意：配置注释里第 7 类可能写作 `pit`，但 `make_terrain` 实际调用的是
     `climb_terrain`，别被名字骗了；
   - 先跑 `play.py --terrain=climb` / `--terrain=gap` 看默认难度下的表现。

2. **做一个 `go2_parkour` 配置**
   - 复制 `go2_amp_config.py`；
   - 地形比例：gap 0.4、climb 0.4、stairs up/down 各 0.1；
   - 环境数固定 512（与 R0/R3 一致），相机环境沿用核心实验配置，显存不够只降相机；
   - 奖励先完全复用 WMP，不要一上来加新项。

3. **只加最小的奖励/终止条件**
   - 跳远：前进速度 + 起跳向上的冲量 + 落地稳定；掉进沟里立即终止；
   - 爬高：base 高度上升 + 前进到平台；从平台掉下去立即终止；
   - 其他奖励（姿态、能耗、AMP）保持 WMP 原样。

4. **用课程 + 微调，不要从零训**
   - 对照组从阶段 3 的 **R0-LHR** checkpoint 初始化，微调 2000~5000 iterations；
   - 课程从 1.5× 开始，逐步加到 3.0×；
   - 主选从阶段 **6A 的 R3（等变世界模型 + 等变 Actor-Critic）** checkpoint 初始化，同样微调；
   - 只有 6A 失败时才退到 **R2**，并在报告里注明；
   - 两组用完全相同的 iteration 数、地形种子、命令采样。

5. **难度阶梯评估**
   - 档位按归一化倍数：1.0× / 1.5× / 2.0× / 2.5× / 3.0×；
   - Go2 对应：沟宽 0.39 / 0.58 / 0.77 / 0.97 / 1.16 m；
     台高 0.33 / 0.50 / 0.66 / 0.83 / 1.00 m；
   - 每档 **200 次**，固定命令，确定性动作；
   - 同时记录绝对米数和归一化倍数，方便和论文 Table IV 对比；
   - 再做一次左右镜像版本，看对称版是否更稳。

**验收**

- 至少一个技能达到 **≥ 2.0×**（Go2 约 0.77 m 沟 / 0.66 m 台），最好到 3.0×；
- 同一难度下，R3（等变世界模型 + 等变 AC）的成功率或极限能力 ≥ R0-LHR 基线；R3 未完成则退 R2 并注明；
- 有 2 段侧视对比视频，标注起跳/落地；
- 有一张“归一化难度-成功率”曲线；
- 如果只做到 1.5× 甚至更低，也算完成：交付地形、评估脚本、负结果分析，
  报告里写清楚“卡在哪、为什么”。

**卡住怎么办**

- Go2 力量不够、打滑、翻车：降到 2.0× 或 1.5×，不要中途换机器人；
- 训练不收敛：退回单一技能，固定地形，降低难度；
- 奖励难调：完全用 WMP 原奖励，只加“掉下去终止”；
- 时间不够：只做 3 个难度点 + 定性视频，不做完整曲线；
- 导师坚持绝对 2.13 / 1.63：停下来讨论换机器人，不要伪造数字；
- 任何情况下，不要为了这个阶段改核心代码、不要重跑核心实验。

**预计时间**

- 微调 + 评估：5~7 天；
- 从零训练：2~3 周（不建议）；
- 换更大机器人：2~4 周（超出 8 周范围，需单独立项）。

**T4 对称变换**
```
新建 symmetry.py，实现观测/动作/潜变量的左右镜像变换。
参考 SWAP 论文 Table I：base 线速度 (vx,-vy,vz)，角速度 (-wx,wy,-wz)，
```

**T5 SymLoss（R1）**
```
在 R0-LHR 的普通 actor/critic + 普通 WMP 上，只在 PPO loss 里加一项镜像一致性软惩罚。
不要改网络结构，不要加 SE 层，不要改世界模型。
要求：
- 用 symmetry.py 的 F_obs/F_act 生成镜像观测和镜像动作；
- 默认只罚 actor：L_sym = mean((actor(F_obs(o), h) - F_act(actor(o, h)))^2)，
  h 固定为同一份并 detach（不反传到普通世界模型）；
- 可选 critic 项 beta * mean((critic(F_obs(o), h) - critic(o, h))^2)，beta 默认 0；
- loss = loss_ppo + lambda_sym * L_sym，lambda_sym 先取 0.01~0.1；
- 单测：dummy 对称 actor loss≈0，dummy 不对称 actor loss>0；actor 有梯度；
- 跑 1k iter，记录 reward、对称误差、lambda_sym，确认不崩。
验收：单测 + 1k 日志 + 对称误差曲线。
注意：这是软约束，不是等变网络；报告写“对称误差下降”，不要写“严格等变”。
```

**T8c SE-MLP（R3）**
```
在 R2 的等变世界模型上，把 actor/critic 换成 SE-MLP。
要求：
- actor 满足 mu(F_obs(o), F_l(h)) = F_act(mu(o, h))；
- critic 满足 V(F_obs(o), F_l(h)) = V(o, h)；
- h 来自等变世界模型的成对潜变量，必须用 F_l(h) 镜像，不能固定 h；
- 保持 sg(h)；
- 写 100 次随机输入的等变测试（float64，SE 线性层 <1e-6，其余 <1e-4）；
- 先只改 actor，critic 保持普通，跑 100 iter 确认能走；再改 critic。
验收：单测 + 100 iter 日志 + 视频。
```

## 七、最容易翻车的 10 个地方

1. **显存爆**
   基线已冻结为 `num_envs=512`、10k≈24 h；不要改回 4096。
   真爆显存时只降 `camera_num_envs`，并重跑同配置 R0-LHR，保证四组可比。
2. **Isaac Gym 版本**
   WMP 要 Preview 3，你的仓库可能用 Preview 4。两个环境分开建，别混。
3. **Go2 关节顺序转错（静默失败）**
   A1 是 FR/FL/RR/RL，Go2 是 FL/FR/RL/RR。转错程序不报错，
   但 AMP 会学出“顺拐”。必须跑 `check_motion_order.py`，看到 `ALL CHECKS PASSED` 才继续。
4. **Go2 深度相机被头挡住（静默失败）**
   A1 的相机位置 `[0.27,0,0.03]` 在 Go2 头壳里面。必须跑 `check_go2_depth.py`
   看 `go2_depth.png`，`near fraction < 0.10` 才继续。否则世界模型学的是后脑勺。
5. **对称性写错但程序不报错**
   等变性错误是“静默失败”：训练照样跑，效果就是不好。
   一定要写 `f(F(x)) == F(f(x))` 的单元测试，每个模块都测。
6. **一上来就改世界模型**
   先得到 R0-LHR 基线，再加 SymLoss 软约束（R1），再把世界模型做成等变（R2），
   最后加等变 actor/critic（R3）。顺序反了，你很难判断问题出在哪。
7. **agent 说“完成了”但没验证**
   永远要求它给：单元测试、loss 曲线、短视频。没有这三样，不算完成。
8. **为了“游刃有余”牺牲核心交付**
   阶段 9 只能在核心报告冻结后启动。爬高/跳远失败不丢人，核心实验没做完才丢人。
9. **四组条件 / 评估标签混用**
   - R1 是 **SymLoss 软约束**，网络结构不变；不要写成“等变网络”。
   - R2 是 **等变世界模型 + 普通 AC**；不要顺手把 AC 换成 SE。
   - R3 是 **等变世界模型 + 等变 AC**；不要复用 R2 的普通 AC checkpoint。
   - 每次评估必须写清：**条件、训练地形（LHR）、模型/checkpoint、评估地形（LHR/RHL）、难度、试验数**。
   - **不要把 LHR 和 RHL 平均成一个“成功率”**；镜像 gap 要单独算。
10. **旧 R0 不是 LHR，不能拿来当基线**
    已确认旧的 10k（**R0-pilot**）**不是固定 LHR**；它只能做环境/冒烟参考，
    **不能进入四组表、图、视频对比**。正式 **R0 必须在阶段 3 用固定 LHR 从零重训 10k**
    （512 env，约 24 h）。
    训练前可视化/打印 height field，确认 tilted box/stair/gap 都是**左高右低**、不随机翻转；
    训练后先 `play.py` 能走，再评估。所有四组表/图里的 **R0 都指 R0-LHR**；
    不要把 R0-pilot 和 R0-LHR 的 checkpoint、训练曲线、成功率混在一起。

## 十、一句话总结

**SWAP 有现成的 WMP 底座，PointWalker 没有代码。**
你现在的目标不是“从零证明自己会写世界模型”，
而是“站在 WMP 上，把对称等变这一块补出来，做出论文里的对比曲线”。
基线仍为 **512 env × 10k ≈ 24 h**；旧 10k 不是固定 LHR，记 **R0-pilot**，
正式 **R0 在阶段 3 用 LHR 重训**；之后按**论文同款四组**推进：
**R0 基线、R1 SymLoss 软约束、R2 等变世界模型 + 普通 AC、R3 等变世界模型 + 等变 AC**。
四组都只在 **LHR（左高右低）** 训练，评估分 **同向 LHR** 和 **镜像 RHL** 两套，必须分开报告；
每次评估写清“条件 / 训练地形 / 模型 / 评估地形 / 难度 / 试验数”。
“游刃有余阶段”以 **R3** 为主选、R0-LHR 为对照；评估统一 **200 次/格**。
先重训 R0-LHR，再加 SymLoss（R1），再做等变世界模型（R2），最后加等变 AC（R3）——这就是最稳的轻量复现路线。
